# Release gates

Status at delivery: source candidate only. Check each item with evidence, not optimism.

1. Confirm the current repository and input ZIP differences; review the replacement diff on a feature branch.
2. Obtain the actual rights holders' code-licence decision and complete DESCRIPTION authors, roles and maintainer email. Keep atlas terms separate.
3. Generate canonical Rd/NAMESPACE from roxygen comments and review warnings; ensure source examples and installed help agree.
4. Install from a clean environment and execute the synthetic example, all Python tests, all R tests and R CMD check. Install optional frameworks so their tests do not merely skip.
5. Run the supplied CI on supported operating systems and publish the actual logs. CI configuration is not evidence of a successful run.
6. Download the pinned real manifest and verify every route, especially native HMBA metadata file discovery. Review schema-specific overrides and add regression fixtures for actual layouts.
7. Compare expression selections against independent AnnData reads on real source data; check native feature panels, huge cell labels, donor joins, taxonomy mappings and anatomical coordinates.
8. Test multiple source shards and both cohorts where biologically applicable. Document unavailable products, unknown classifications and the Patch-seq non-neuronal N/A case.
9. Benchmark frozen selections using unique empty caches and genuine warm repeats, at least three technical repeats where practical. Archive failures, missing measurements, environment, source-file plans, selections and results.
10. Compare against the official SDK plus explicit R conversion, or a justified equivalent workflow, before making efficiency or convenience claims. Do not claim HPC avoidance or universal runtime superiority from small selected outputs alone.
11. Pin the tested upstream SDK commit and data manifest; record R and Python dependency locks, package commit, OS and machine specifications. Re-run after the lock is established.
12. Tag a stable release, archive it with a real identifier, verify the stable download, and commit to the required availability period. No DOI or licence in this bundle is fabricated.
13. Authors independently write the submission text under the current journal/ISCB LLM policy, verify all references, disclose permitted assistance, supply real author/funding/conflict/contact information and replace missing results with measured evidence.
14. Format the eventual article and one genuine runtime figure to the journal's page/word/figure requirements. Confirm the journal policy again immediately before submission; fit and acceptance are not guaranteed.
